    异常安全（Exception Safety）¶

    iNote

    异常安全的重点不是"会不会抛异常"，而是抛异常后对象的资源、状态和业务不变式是否仍然成立——这是区分专业 C++ 工程代码和"看起来能跑"的代码的分水岭。

    1. 三个保证级别¶

    级别 含义 实现手段
    基本保证 不泄漏资源，对象保持可析构状态。状态可能已改变但合法 RAII 管理所有资源
    强保证 操作要么完全成功，要么回滚到调用前的状态（commit-or-rollback） 拷贝交换（copy-and-swap）
    不抛异常保证 函数承诺不抛出异常 noexcept 声明

    为什么 noexcept 对容器性能至关重要¶

    std::vector<Buffer> v;
v.push_back(Buffer(1024));  // 扩容时：

// 如果 Buffer 的移动构造是 noexcept → 用移动（高效）
static_assert(std::is_nothrow_move_constructible_v<Buffer>);

// 如果不是 noexcept → 退化用拷贝（安全但慢）
// 原因：移动中途抛异常，源对象已损坏，无法回滚 → 强保证破灭

    2. 拷贝交换（Copy-and-Swap）实现强保证¶

    class Buffer {
    char* data_;
    size_t size_;

public:
    // 不抛异常的 swap
    void swap(Buffer& other) noexcept {
        std::swap(data_, other.data_);
        std::swap(size_, other.size_);
    }

    // 赋值运算符：强保证
    Buffer& operator=(const Buffer& other) {
        Buffer temp(other);   // ① 先在新对象上尝试所有可能失败的操作
        swap(temp);           // ② 不抛异常的交换——原子替换状态
        return *this;
    }  // ③ temp 析构释放旧资源
};

    关键：把可能失败的操作（拷贝）放在临时对象上，成功后再用不抛异常的 swap 替换。如果拷贝失败，*this 完全不变（强保证）。

    3. 工程实践¶

    场景 推荐做法
    析构函数 绝不抛异常（隐式 noexcept）
    移动构造/赋值 标注 noexcept
    swap 标注 noexcept
    简单 getter/setter 标注 noexcept
    含资源分配的赋值 拷贝交换模式

    4. 关联概念¶

    • RAII（资源获取即初始化） — RAII 是异常安全的基础：资源由对象管理，异常展开时自动析构
    • 移动语义与完美转发 — noexcept 移动构造是容器性能优化的前提
    • 智能指针三者对比（unique_ptr / shared_ptr / weak_ptr） — 智能指针保证基本异常安全（不泄漏），拷贝交换提供强保证
    • lock_guard vs unique_lock 对比 — lock_guard 保证锁的异常安全释放
